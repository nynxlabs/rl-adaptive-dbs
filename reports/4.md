## Compute upgrade: AMD Ryzen 7 5800X (8c/16t) → Ryzen 9 5900XT (16c/32t)

Report 3 listed a workstation compute upgrade as upcoming work. That upgrade is **done** (August 2026): the training workstation is now **AMD Ryzen 9 5900XT** (**16 cores / 32 threads**), replacing the previous **AMD Ryzen 7 5800X** (**8 cores / 16 threads**) that carried most replication trains since Report 1.

### Why it matters for this project

**One train at a time is not much faster.** Each replication run caps in-process plant math at **1** thread (`OMP_NUM_THREADS=1`, etc.), so a single Mehregan/Nguyen/Ravivarapu episode still spends ~the same wall-clock on the biophysical integrate loop. Because the neural ODE plant integration is pure floating-point math, one simulation run fully saturates one physical core's arithmetic execution pipeline. The upgrade buys **dedicated physical core concurrency and parallel sweep capacity**, not a magic speedup on one isolated 500-episode job.

| Area | Before: Ryzen 7 5800X (8 cores / 16 threads) | Now: Ryzen 9 5900XT (16 cores / 32 threads) |
|------|-----------------------------------------------|---------------------------------------------|
| **Parallel worker capacity** | Reserving 2 cores for OS, desktop, and tooling left **6 concurrent simulation workers** max. A 4-variant ablation panel consumed nearly all available capacity. | Reserving 2–4 cores for OS, desktop, and tooling leaves **12–14 dedicated simulation workers** running at 100% full speed without SMT thread contention. |
| **Multi-seed / ablation sweeps** | Running a 4-variant ablation across 3 seeds (12 runs total) required queuing across multiple serial batches. | Run an entire 12-run sweep (e.g., all 4 ablation variants across 3 seeds simultaneously) in a single parallel batch. |
| **Multitasking & eval** | Running continuous parameter sweeps alongside local evaluation and plotting scripts caused UI sluggishness and process contention. | **Headroom to spare**: keep 12 full simulation sweeps running in the background while compiling figures, analyzing data, and running desktop tools. |
| **Calendar time on sweeps** | Nguyen Fig. 4: each full train still hours; hyperparameter tuning waited on serial completion. | More **parallel sweep lanes** → more completed trains per week, not faster individual trains. |

cd rl-adaptive-dbs
