## Kumaravelu et al. (2016) model

- **Source.** Kumaravelu K, Brocker DT, Grill WM (2016). *A biophysical model of the cortex–basal ganglia–thalamus network in the 6-OHDA lesioned rat model of Parkinson's disease.* J Comput Neurosci 40:207–229. ModelDB accession 206232 (version dated 2016-12-12), mirrored at [ModelDBRepository/206232](https://github.com/ModelDBRepository/206232).
- **Exact revision.** Our first copy of `simulate_network_model.m` is identical to the mirror's commit `0addcc04d7e6f16213a937591e4d2952e3a911ed` (2016-12-12, which includes the author's typo update). Our later edits are integration-only and are listed in [changes.md](reference-material/KumaraveluEtAl2016/changes.md).
- **Not redistributed (since October 2026).** This repository no longer ships the model's files. [`scripts/matlab/fetch_kumaravelu.py`](scripts/matlab/fetch_kumaravelu.py) downloads `simulate_network_model.m`, `run_simulate_network_model.q`, and `readme.txt` at that commit from the GitHub mirror, checks each against a recorded SHA-256, applies our patches from [`patches/`](reference-material/KumaraveluEtAl2016/patches/), and checks the results against [`patches/manifest.json`](reference-material/KumaraveluEtAl2016/patches/manifest.json). The output goes to gitignored files in `reference-material/KumaraveluEtAl2016/`. The patches are zero-context diffs, so they carry our added lines plus only the upstream lines our edits replace (31 short lines of `simulate_network_model.m` and the 9-line `make_Spectrum` function). Earlier commits in this repository's git history still contain the full files; that history has not been rewritten.
- **License status.** We have not found a license or reuse grant for this model. The upstream files carry no license, copyright, or permission text, the GitHub mirror declares no license, and ModelDB's model record and citation page ask for citation without stating license terms. Not finding a license is not the same as a finding that reuse is prohibited. It does mean the MIT License in this repository **does not** apply to this model, and we have not been granted the right to relicense it.
- **Status: permission pending.** We may ask the rights holder for an explicit open-source grant that covers the model, our modifications, and the Python port; with one, the files could be bundled again. Until then, treat the model and everything derived from it as not cleared for redistribution under MIT.

## Chronux helpers (GNU GPL v2)

`simulate_network_model.m` (from the upstream model) contains these Chronux routines: `mtspectrumpt`, `getparams`, `change_row_to_column`, `minmaxsptimes`, `getfgrid`, `dpsschk`, `mtfftpt`, and `specerr`. `plant_band_power.m` contains copies of all of them except `specerr`. Neither file is in this repository any more: the fetch script takes `simulate_network_model.m` from upstream and builds `plant_band_power.m` from it (the upstream lines from `make_Spectrum` up to `specerr`, plus our patch). Nothing in the repository itself is Chronux code; `CHRONUX_LICENSE.txt` stays so the fetched files have their license text next to them.

- **Provenance.** Chronux is an open-source neural data analysis toolbox originally developed at the Mitra Lab, Cold Spring Harbor Laboratory ([chronux.org](http://chronux.org/)). Ignoring whitespace and comments, the code of these routines is the same as in Chronux 2.10, 2.11, and 2.12. The only differences are an added closing `end` on each local function and `-i` written as `-1i` in `mtfftpt`. The routines are identical across those releases, so we cannot tell which one upstream copied from. Upstream removed Chronux's header comments when it inlined them.
- **License.** Chronux is distributed under the GNU General Public License, version 2. Its release notes state: "As an open source project released under the GNU Public License GPL v2". [CHRONUX_LICENSE.txt](reference-material/KumaraveluEtAl2016/CHRONUX_LICENSE.txt) is a byte-for-byte copy of the `License.txt` shipped in Chronux 2.10 and 2.11 (SHA-256 `a600b43a1526893825caa08fce76177315d6b158e36ae0fbce8af9bb2f57eede`), including Chronux's note on parts of its distribution the license may not apply to.
- **Notices.** Our patches add a notice to each fetched `.m` file marking where its Chronux block begins and pointing to the license text.
- **Combined files.** Both fetched `.m` files also contain code that is not Chronux's: the Kumaravelu model in `simulate_network_model.m`, and in `plant_band_power.m` a `make_Spectrum`-style wrapper (adapted from the upstream file) plus our `plant_p_beta`. We do not declare either whole file GPL. The model code in it is not ours to license, and its own status is pending (above). Because we no longer distribute these files, the question of how GPL v2's terms for combined works apply to them no longer arises for this repository's current tree.
- **Python.** `src/envs/plant/biomarkers.py` computes the same point-process multitaper spectrum with SciPy (`scipy.signal.windows.dpss`) rather than calling Chronux. It is listed here because its structure follows `mtspectrumpt`. It has not been independently reviewed as a separate implementation.

## Native Python port of the model

The port stays in the repository: every replication runs on it. These files translate the Kumaravelu MATLAB model into Python, or carry its parameters and conventions. Our own work in them (structure, Numba/NumPy implementation, caching, API) is ours. The scientific model itself (its equations, parameter values, and methods) is not what is at issue here. The open question is how far our implementation follows the MATLAB source code's own expression (its structure, naming, and ordering), since it was produced by translating that code. Until permission is settled, we do not offer the source-derived parts of these files under our MIT License:

- `src/envs/plant/network/integrator.py`, `gating.py`, `synapses.py`, `numba_loop.py`
- `src/envs/plant/dbs.py`, `spikes.py`, `config.py`, `python_backend.py`
- `src/envs/plant/biomarkers.py` (spectrum estimate; see Chronux above)

`src/envs/plant/network/matlab_rng.py` reproduces MATLAB's random-number draw order. It is not a translation of the model.

## Data generated by the model

`tests/fixtures/plant_init_seed*.npz` and `creatdbs_130hz.npz` are outputs of the MATLAB model (initial-condition draws exported with `scripts/plant/export_plant_init_draws.py`, and a DBS waveform). They stay in the repository: the Python plant loads the init draws at reset, and regenerating them needs a licensed MATLAB install, so they are not cheap to rebuild from the fetched model. They are treated as pending with the model.

## Python package metadata

The installable package (`pyproject.toml`) contains the plant port, so its license expression is `MIT AND LicenseRef-Kumaravelu-2016-Pending`, and it ships this file next to `LICENSE`. The custom identifier means: part of the package is derived from the Kumaravelu et al. (2016) model, whose license is pending as described above. The source distribution is limited to `src/` and the package metadata files, so it leaves out our model patches, the paper figure crops, the reports, and the test fixtures.
