## Kumaravelu et al. (2016) model

- **Source.** Kumaravelu K, Brocker DT, Grill WM (2016). *A biophysical model of the cortex–basal ganglia–thalamus network in the 6-OHDA lesioned rat model of Parkinson's disease.* J Comput Neurosci 40:207–229. ModelDB accession 206232 (version dated 2016-12-12), mirrored at [ModelDBRepository/206232](https://github.com/ModelDBRepository/206232).
- **Exact revision.** Our first copy of `simulate_network_model.m` is identical to the mirror's commit `0addcc04d7e6f16213a937591e4d2952e3a911ed` (2016-12-12, which includes the author's typo update). Our later edits are integration-only and are listed in [changes.md](reference-material/KumaraveluEtAl2016/changes.md).
- **Not redistributed (since October 2026).** This repository no longer ships the model's files. [`scripts/matlab/fetch_kumaravelu.py`](scripts/matlab/fetch_kumaravelu.py) downloads `simulate_network_model.m`, `run_simulate_network_model.q`, and `readme.txt` at that commit from the GitHub mirror, checks each against a recorded SHA-256, and writes them to gitignored files in `reference-material/KumaraveluEtAl2016/`.
- **Our patches are private too (since October 18, 2026).** Our edits to the model are zero-context diffs, so they carry our added lines plus the upstream lines our edits replace (31 short lines of `simulate_network_model.m` and the 9-line `make_Spectrum` function). Because they quote the model, they moved to the private `kumaravelu_plant` package with the Python port. When that package is installed, the fetch script applies them and checks the results against their `manifest.json`; without it, the script writes the unmodified upstream files and says so. The MATLAB plant bridge (`MatlabPlant`) needs the patched copy.
- **License status.** We have not found a license or reuse grant for this model. The upstream files carry no license, copyright, or permission text, the GitHub mirror declares no license, and ModelDB's model record and citation page ask for citation without stating license terms. Not finding a license is not the same as a finding that reuse is prohibited. It does mean the MIT License in this repository **does not** apply to this model, and we have not been granted the right to relicense it.
- **Status: permission pending.** We may ask the rights holder for an explicit open-source grant that covers the model, our modifications, and the Python port; with one, the files could return to this repository. Until then, everything derived from the model's code (the Python port, our patches, and the data the model generated) stays in a private package, `kumaravelu_plant`, and is not offered under any license. Without that package this repository installs, imports, and passes its tests (plant tests skip), but it cannot run the plant: plant use raises `PlantUnavailableError`, which points here.

## Chronux helpers (GNU GPL v2)

`simulate_network_model.m` (from the upstream model) contains these Chronux routines: `mtspectrumpt`, `getparams`, `change_row_to_column`, `minmaxsptimes`, `getfgrid`, `dpsschk`, `mtfftpt`, and `specerr`. `plant_band_power.m` contains copies of all of them except `specerr`. Neither file is in this repository any more: the fetch script takes `simulate_network_model.m` from upstream and builds `plant_band_power.m` from it (the upstream lines from `make_Spectrum` up to `specerr`, plus our patch). Nothing in the repository itself is Chronux code; `CHRONUX_LICENSE.txt` stays so the fetched files have their license text next to them.

- **Provenance.** Chronux is an open-source neural data analysis toolbox originally developed at the Mitra Lab, Cold Spring Harbor Laboratory ([chronux.org](http://chronux.org/)). Ignoring whitespace and comments, the code of these routines is the same as in Chronux 2.10, 2.11, and 2.12. The only differences are an added closing `end` on each local function and `-i` written as `-1i` in `mtfftpt`. The routines are identical across those releases, so we cannot tell which one upstream copied from. Upstream removed Chronux's header comments when it inlined them.
- **License.** Chronux is distributed under the GNU General Public License, version 2. Its release notes state: "As an open source project released under the GNU Public License GPL v2". [CHRONUX_LICENSE.txt](reference-material/KumaraveluEtAl2016/CHRONUX_LICENSE.txt) is a byte-for-byte copy of the `License.txt` shipped in Chronux 2.10 and 2.11 (SHA-256 `a600b43a1526893825caa08fce76177315d6b158e36ae0fbce8af9bb2f57eede`), including Chronux's note on parts of its distribution the license may not apply to.
- **Notices.** Our patches (private, see above) add a notice to each patched `.m` file marking where its Chronux block begins and pointing to the license text.
- **Combined files.** Both fetched `.m` files also contain code that is not Chronux's: the Kumaravelu model in `simulate_network_model.m`, and in `plant_band_power.m` a `make_Spectrum`-style wrapper (adapted from the upstream file) plus our `plant_p_beta`. We do not declare either whole file GPL. The model code in it is not ours to license, and its own status is pending (above). Because we no longer distribute these files, the question of how GPL v2's terms for combined works apply to them no longer arises for this repository's current tree.
- **Python.** The private `kumaravelu_plant` package computes the same point-process multitaper spectrum with SciPy (`scipy.signal.windows.dpss`) rather than calling Chronux; its structure follows `mtspectrumpt` and the model's `make_Spectrum`, which is why it moved out with the port. This repository no longer contains it.

## Native Python port of the model

Every replication runs on our native Python port of the model. The port translates the Kumaravelu MATLAB code into Python, so it follows that code's own expression (structure, naming, ordering), not just its published equations and parameter values. Until permission is settled, it lives in a private package, `kumaravelu_plant`, not in this repository. This repository reaches it through one module, [`src/envs/plant/_kumaravelu.py`](src/envs/plant/_kumaravelu.py): the public names below resolve to the package on first use, and raise `PlantUnavailableError` when it is missing.

**Stayed here, and why.** Where a listed file mixed translated code with our own, we split it and kept our part:

- `src/envs/plant/config.py` stays whole. `PlantConfig` is our settings type; the SMC defaults come from Gao et al. and Jovanov et al., not the model. Its two Kumaravelu values (thalamic bias current 1.2 and GPi→thalamus conductance 0.112) are published parameter values, not code expression.
- `src/envs/plant/dbs.py` keeps `DbsSpec` (our index into the model's 0–200 Hz frequency grid), `stn_dbs_gains` (our STN spread model, not in Kumaravelu), `ContinuousPulseTrain` (our phase-continuous pulse train), and the published pulse width and amplitude.
- `src/envs/plant/spikes.py` keeps our MATLAB-engine converters and `spike_counts`.
- `src/envs/plant/biomarkers.py` keeps the band limits and the Error Index functions, which follow Gao et al. (ICCPS 2020) and Mehregan et al., not the model's code.
- `src/envs/plant/matlab_backend.py` (our MATLAB-engine bridge) and `src/envs/plant/network/matlab_rng.py` (MATLAB's random-number draw order) are ours. `matlab_rng`'s fixture check names the model's cortex→D1 striatum conductance range (one parameter relation, not translated code).
- `src/envs/plant/network/integrator.py` moved whole, including a few helpers of ours inside it (the SMC pulse schedules). They are interleaved with the port, so we did not split them out.
- `src/envs/plant/python_backend.py` is mostly our wrapper code, but it only drives the port, so it moved with it.

Earlier commits in this repository's git history contain the moved files.

**Published figures are not in this repository.** Until October 2026 it held crops of the published IEEE figures (`figures/*/images/*/paper.png`), a pasted crop in `docs/reports/images/`, and the progress-report PDFs that embedded them (`docs/reports/*.pdf`). Those are the publishers' material, and we had no permission or clear exception to republish them, so they were removed from the repository and from its entire git history. **Local crops for digitization.** The digitization tools in `scripts/digitization/` read a crop of each published panel. `scripts/digitization/paper_crops.py build` makes those crops on your machine from your own copy of each paper (where it looks for the PDFs: `scripts/digitization/README.md`). `paper_crops.json` records only where each panel sits on its page (page number and box), not image content. The crops it writes are gitignored and must never be committed.

**What the public comparisons show instead.**

- **Mehregan et al. and Nguyen et al.:** our own plot of the values we digitized from each panel (`digitized_v*.png`), captioned "Digitized from Fig. N of …". It is a new drawing of the data, not a copy of the figure. The replication plots overlay the same digitized values.

Each file is cropped from the matching figure of the arXiv PDF; the only change is cropping. The authors do not endorse this project. We compared each arXiv crop with the matching published figure: the curves, legends, and panel captions are the same, at a slightly different scale.

### Digitized values

The curves we compare against are numbers read off the published figures (WebPlotDigitizer and color-mask tracing; `scripts/digitization/`). We treat them as data, not as the figures' expression: copyright protects how a figure presents its results, not the underlying facts and measurements (in the US, *Feist v. Rural* and 17 U.S.C. § 102(b)). We publish:

- our plots of those values, drawn with our own code and style and labelled as digitized from the cited figure;
- the summary numbers our gates check (window means, ratios, timings), which live in the gate code.

The digitized curve files (`artifacts/…/curves_*.json`) stay local, like all of `artifacts/`. We do not claim the values themselves as ours, and they are not offered under MIT or any license. This is our reasoning, not a legal opinion.

## Data generated by the model

The initial-condition draws the Python plant loads at reset (`plant_init_seed{N}.npz` for the PD network and `plant_init_seed{N}_pd0.npz` for the healthy one, exported from the MATLAB model with `scripts/plant/export_plant_init_draws.py`) and a reference DBS waveform (`creatdbs_130hz.npz`) are outputs of the model. They used to be in `tests/fixtures/`; they are now in the private `kumaravelu_plant` package with the port, and the export script writes new ones there. Regenerating them needs a licensed MATLAB install and the patched model.

## Python package metadata

The installable package (`pyproject.toml`) no longer contains code derived from the Kumaravelu model, so its license expression is `MIT`; it ships this file next to `LICENSE`. The source distribution is limited to `src/` and the package metadata files, so it leaves out the figures and the reports. This project has not published a package.
